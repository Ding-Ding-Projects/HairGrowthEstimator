# 頭髮生長估算

## 行為

估算器會根據有日期嘅基準、每月生長率估算值同目標，推算頭髮長度。產品預設係可以調整嘅 **每月 1.0 cm** 估算值。呢個係規劃用數值，唔係某個人身上量度出嚟嘅事實。唔同人嘅頭髮生長速度可以有明顯分別，同一個人喺唔同時間亦會變。

估算唔係醫療建議，唔可以診斷頭髮或頭皮狀況，亦唔可以預測個別人士實際生長速度。呢條邊界嘅背景資料來自臨床概覽 [Hair Growth Disorders, StatPearls](https://www.ncbi.nlm.nih.gov/books/NBK499948/)。如果自己記錄到嘅量度結果同預設唔同，使用者應該記錄量度值，再調整生長率，唔使迫自己啲頭髮跟預設返工。

Version 1 profile schema 會儲存厘米基準長度、基準日期、以厘米表示嘅每月生長率、目標長度，同偏好顯示單位。瀏覽器狀態另外保留手動後備日期同長度。最新而有效嘅剩餘剪髮紀錄係瀏覽器目前使用嘅基準。將一項剪髮紀錄改成較早日期，或者刪除紀錄之後，程式會再由所有剩餘紀錄揀選有效基準。當再冇有效剪髮紀錄，程式會使用保留嘅手動後備值，而唔會由已刪除紀錄重新製造一份。

目前長度計算同預計達標計算共用同一份日曆合約：`365.2425 / 12 = 30.436875 days per estimate month`。目前長度計算使用 `baseline length + monthly rate × (elapsed days / 30.436875)`，之後將結果限制為最少零。預計達標計算會將剩餘長度除以每月生長率，再用同一個 30.436875 日數值將月份轉返日數。基準日期必須係今日或之前。新輸入嘅未來日期會喺欄位旁邊被拒絕。舊有未來日期剪髮紀錄仍然會顯示，但只要日期仲喺未來，就唔會參與有效基準選擇。如果冇有效剪髮紀錄可以優先使用，而手動後備日期又喺未來，估算會清楚顯示為不可用。已檢查嘅桌面原始碼仲未同文件寫明嘅每月 1.0 cm 預設值對齊，所以跨介面預設值驗證仍然有待完成。

## 設定

Profile 欄位儲存喺本機 version 1 狀態嘅 `profile` 之下。HTTP 服務透過 `PUT /api/profiles/{profileId}` 接受相同嘅正規化欄位。服務將數值長度同生長率限制喺 0 至 300 厘米，並接受 `YYYY-MM-DD` 格式日期。網站估算器為每月生長率訂立較窄嘅 0 至 10 輸入範圍。任何會轉換單位嘅介面，都必須轉換輸入值同顯示結果，但唔可以改變正式厘米值。

網站基準欄位會編輯保留嘅手動後備值。估算結果正上方嘅有效基準狀態，會直接講明而家用緊最新有效剪髮紀錄，定係手動後備值。兩個日期欄位都會用訪客目前本地日期做最大值，並提供同輸入欄位保持關聯嘅 inline error，方便 assistive technology 讀取。

## 失敗情況

- 傳送到服務嘅無效 profile 會收到 HTTP 400，同時附有長度受限嘅錯誤訊息。
- 本機狀態檔案缺失時，會使用 version 1 預設值。
- 喺已檢查嘅桌面主程序入面，語法無效嘅本機狀態檔案同樣會回退到預設值。呢個行為可能掩蓋資料損壞，仍然需要面向使用者嘅復原通知。
- 生長率為零時，除非目標已經達成，否則無法推算較後嘅目標日期。
- 未來或無效嘅手動基準會喺新值儲存之前被拒絕。如果載入較舊、日期喺未來嘅手動值，而又冇有效剪髮紀錄，結果會顯示為不可用，而唔係強行將經過日數壓成零。
- 已儲存嘅未來日期剪髮紀錄仍然可以檢視，但只要日期仲喺未來，就唔可以成為有效基準。改返今日或之前之後，佢會即時符合資格。
- 目標低過估算目前長度時，會報告目標已經達成。
- 原始碼預設值如果同文件寫明嘅每月 1.0 cm 唔同，就會阻止發佈驗證，直至兩邊對齊。
- 瀏覽器計算未經 composed artifact 實際操作之前，唔可以視為已驗證。

## 安全同私隱

Profile 值係一般個人紀錄，預設只儲存喺本機。只有使用者選擇 server-backed workflow 時，資料先會傳送到伺服器。Server URL 會拒絕內嵌 credential。桌面主程序會將 API key 放喺 JSON 設定檔案之外。估算唔可以被包裝成醫療指引，亦唔可以傳送去 analytics、廣告或圖片服務。

## 驗證

原始碼檢查確認 `app/main.js` 入面嘅 profile schema、`site/index.template.html` 入面嘅估算器控制、`site/app.js` 入面嘅瀏覽器計算同持久化、`site/state-contract.js` 入面嘅基準選擇同日期順序驗證，以及 `server/index.js` 入面嘅服務驗證。`tests/site/correctness.test.mjs` 證明最新紀錄選擇、編輯同刪除後重新選擇、保留手動後備值、拒絕未來日期，同排除舊有未來剪髮紀錄。`tests/site/month-parity.test.mjs` 會使用完整、部分、已達標同零生長率情況嘅共用確定性向量，亦會刻意喺原始碼同文件還原舊月份近似值，證明兩條邊界都會轉紅。瀏覽器互動、單位切換顯示、跨介面使用共用向量，同成品擷取仍然有待完成。
