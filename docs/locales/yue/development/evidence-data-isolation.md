# 只供證據使用嘅資料隔離

## 啟動合約

無畫面證據工具會用以下三個精確開關啟動程式：

```text
--evidence-mode
--evidence-app-data=<absolute-empty-task-root>
--evidence-user-data=<absolute-empty-task-root>
```

每個開關一定只可以出現一次。兩個路徑都要係絕對、唔同、互不重疊、空白或者未存在，而且要放喺作業系統臨時目錄之下嘅精確 `.hair-growth-evidence-task` 路徑段，亦唔可以包含符號連結或者重解析元件。檔案系統根目錄、相對路徑、臨時目錄以外標記路徑、標記相似字、非空目錄、檔案、重疊同重複值都會停止啟動。

普通模式只會喺完全冇 `--evidence-*` 參數時先揀選。兩個保留資料開關本身永遠唔會獲接受。任何一個如果冇配合精確 `--evidence-mode`，啟動會停止，唔會當成普通模式。模式開關必須精確而且唔接受值，所以 `--evidence-mode=true`、`--evidence-mode=false`、`--evidence-mode=` 同 `--evidence-modee` 都會停止啟動。就算三個必要開關齊全，任何未知 `--evidence-*` 開關一樣會被拒絕。

驗證器會建立通過驗證但未存在嘅根目錄，再檢查每個路徑元件，然後喺就緒或者任何普通程式資料讀取之前啟動兩個 Electron 路徑。普通啟動唔會呼叫 `app.setPath`，亦唔會建立收據。

## 實體路徑識別

只比較文字路徑唔足夠，因為同一實體目錄可以有多個寫法。驗證器會用 `fs.realpathSync.native` 解析每個根目錄。如果最後根目錄仲未存在，程式會向上行到最深嘅現有祖先，以原生方式解析，再加返仍未存在嘅尾段。咁樣可以安全支援未建立嘅空根目錄，同時用實體識別比較長名稱、8.3 名稱、大小寫同連結別名。實體相同、祖先關係或者後代重疊都會停止啟動。

符號連結同重解析檢查仍然分開，並會檢查每個現有元件。檔案系統檢查失敗會停止啟動，而且只回報許可清單內嘅穩定錯誤代碼。未知或者格式錯誤嘅配接器代碼會變成固定 `filesystem_error`。驗證錯誤唔會包含輸入原始路徑或者底層檔案系統錯誤訊息。

## 只含雜湊嘅收據

隔離用戶資料根目錄會收到 `evidence-isolation.json`。隔離程式資料根目錄會收到 `evidence-app-data-active.json`。收據只包含結構版本 1、描述啟用隔離狀態嘅布林值同 SHA-256，永遠唔會包含原始路徑。

標準雜湊會先對正規化絕對路徑做 Unicode NFC，再以 UTF-8 編碼，把反斜線改成 `/`，並喺 Windows 轉成細寫。

## 失敗同私隱行為

被拒絕嘅啟動會喺讀取程式狀態、共用紀錄、憑證或者歷史之前停止。收據用排他方式建立檔案，所以意外重複唔可以覆寫舊證據。收據只留喺可棄置工具儲存，唔會經預載橋接或者畫面公開。實體識別驗證永遠唔記錄輸入路徑。

## 香港粵語

平常啟動要求完全唔出現 `--evidence-*` 參數。隔離證據啟動只認三個指定開關，而且每個只認一次。資料開關一定要同精確 `--evidence-mode` 一齊出現，否則程式即刻停低，絕對唔會偷偷跌返去平常流程。`--evidence-mode` 本身唔收值，所以 `--evidence-mode=true`、`--evidence-mode=false`、`--evidence-mode=` 同 `--evidence-modee` 全部唔合格。三個必要開關齊備之後，額外嘅未知 `--evidence-*` 開關仍然會令啟動停止。

兩個資料根位置都必須用絕對路徑，彼此唔可以交疊，內容要空白或者仲未建立，亦一定要位於作業系統臨時目錄下面嘅精確 `.hair-growth-evidence-task` 路徑段。驗證器透過 `fs.realpathSync.native` 核對真正落碟位置。目標未存在時，程式會逐層向上搵到最深嘅現有祖先，先解析原生位置，之後先接返尚未建立嘅尾段。呢個做法既保留未建立目標，又阻止長名稱、8.3 短名稱、字母大小寫或者連結別名冒充另一個位置。兩邊最後指向同一實體，或者形成祖先與後代關係，都會即時停止啟動。

程式會再逐個檢查連結同重解析點，之後先交畀 Electron 使用，全程早過正常資料讀取。檔案系統檢查如果失敗，只會回報許可清單內嘅穩定錯誤代碼。未知或者格式錯誤嘅代碼會變成固定 `filesystem_error`，唔會記錄用戶提供嘅原始路徑或者底層錯誤訊息。

兩份收據只放版本、布林狀態同路徑 SHA-256，唔會寫原始路徑，亦唔會送去畫面或者預載橋接。
