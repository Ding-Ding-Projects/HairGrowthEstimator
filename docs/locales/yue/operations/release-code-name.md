# 發佈代號同點心記錄

## 行為

第一個計劃中嘅發佈代號係 **Classic Har Gow · 蝦餃**。權威公開目錄記錄係 `hk-dish-0001`。代號只係版本旁邊嘅裝飾，永遠唔會取代語意版本。

權威公開圖片係：

`https://github.com/Ding-Ding-Projects/dim-sum-photos/releases/download/catalog-v1/hk-dish-0001-classic-har-gow.png`

揀選呢筆記錄時使用嘅公開目錄修訂版本係 `736e8c1d9e40e1d146f3c3b11bb329b97c4ef515`。消費端儲存庫唔會複製圖片或者公開目錄，避免整多一份互相拗頭嘅權威資料。

## 設定

發佈組合會將語意版本、雙語菜式名稱、記錄 ID、不可變公開目錄修訂版本同公開資產 URL 一齊記錄。之後每次發佈都會揀另一筆未使用而且已有公開圖片嘅記錄。網站啟動驚喜可以引用同一個公開資產，但佢同八張本機頭髮參考相片仍然係兩回事，唔會撈亂。

## 失敗情況

- 如果無法解析公開目錄或圖片，發佈會保留版本，並如實報告冇附加代號。
- 圖片缺失時，唔可以用生成、下載或者儲存庫追蹤嘅替代品補位。
- 如果之後嘅專案發佈再次使用 `hk-dish-0001`，對應關係就會含糊，必須拒絕。
- 未證實會回傳可解碼圖片嘅公開 URL 仍然屬於未驗證狀態。

## 安全同私隱

公開圖片請求唔包含訪客識別資料、個人檔案值、量度、認證資料或者分析參數。圖片唔會複製到呢個儲存庫、發佈資產、匯出或者瀏覽器本機歷史記錄。公開目錄係菜式名稱同相片嘅唯一權威來源。

## 驗證

組合器會將代號、記錄 ID、公開目錄修訂版本同公開 URL 一齊嵌入成品來源資料，而網站啟動驚喜來源會引用同一個公開資產，唔會複製佢。匿名 URL 擷取、圖片解碼、發佈說明顯示、「關於」介面顯示、組合後網站顯示、未使用名稱檢查，以及最終發佈證據仍然待辦。
