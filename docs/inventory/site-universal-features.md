# Website universal-feature inventory

## Scope and evidence rules

This is the hand-written completeness inventory for the public website surface. It is intentionally not generated from the controls currently found in source, because discovery-only inventory cannot detect a feature that disappears entirely.

The current inspected source boundary includes `site/index.template.html`, `site/styles.css`, `site/state-contract.js`, `site/security-contract.js`, `site/localization-contract.js`, `site/presentation-contract.js`, `site/regex-client.js`, `site/regex-worker.js`, `site/app.js`, the three `site/locales/yue` catalogs, and `scripts/compose-site.mjs`. The strict security contract, localization and presentation contracts, disposable Worker modules, active application consumers, accessibility repair functions, bounded terminal-transfer reader, and runtime installer validator are source present at the anchors recorded below. Source-implemented means an exact function and registration exist, but it does not mean the composed artifact has been exercised. Focused tests cover the four correctness rows that link `tests/site/correctness.test.mjs`. A final three-check accessibility and installer subset also has accepted red-then-green proof. Other focused tests, interaction ledgers, captures, and public deployment proof remain pending.

Negative-regression evidence is partial. The accepted evidence names each exact boundary that was deliberately removed and observed to fail. It never promotes those examples into proof that every inventory row, localization boundary, interaction record, or capture record has its own red-then-green regression.

Source localization is complete for the hand-written L06 boundary: 250 `ui-core`, 274 `ui-settings`, and 686 `runtime` entries plus 50 English and Cantonese article pairs. The five focused localization tests pass after exact catalog-entry deletion and article-locale omission regressions turned red. Any row below that still describes localization as pending uses that state for composed interaction, row-specific rendering, or capture proof, not for a missing source catalog entry. No built-evidence row is closed by source completeness.

Each row records the following boundaries:

- **Implementation** links the current source owner and names its exact selector or module. "Source partial" means some behavior exists but the complete contract is not implemented.
- **Localization** names the copy owner or records that localized resources are missing.
- **Persistence** names browser or product storage and marks an unverified key pending.
- **Focused test ID** is the stable identifier the future focused suite must use. The identifier does not imply that a test exists.
- **Interaction proof** and **capture proof** are required future artifact paths. Every one is pending until produced from a built artifact.
