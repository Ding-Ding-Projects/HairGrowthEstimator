# Support Tickets

## Behavior

Support Tickets is a fictional, browser-local recovery desk reached from the lock prompt, lock settings, and Help. A local ticket has a category, description, generated number, decorative severity, status progression, and canned response. Its practical resolution explains how the user can open browser settings and delete this website's local data themselves.

The surface must always state plainly that nothing is sent, no external ticket exists, no data is collected, and nobody is reading it. The website never claims that it opened an operating-system application-data folder because a static page cannot do that.

## Configuration

The template declares `#support-dialog`, `#ticket-category`, `#ticket-description`, `#create-ticket`, `#ticket-search`, and `#ticket-list`. Ticket records need a versioned local schema, stable local IDs, bounded text, searchable status, bulk export, and bulk deletion through destructive confirmation.

## Failure modes

- Storage refusal must not claim that a ticket was created.
- Failure to open browser site-data settings must leave exact manual instructions.
- Clearing website storage removes the local tickets too.
- The surface never invents a real company, person, response time, or external delivery state.

## Security and privacy

Ticket text remains in browser storage. It is not transmitted, synchronized, logged, or captured from a real user profile. The permanent disclosure remains factual at every language and funny-level setting.

## Verification

Source inspection confirmed local numbering, bounded descriptions, category choice, created, manual-reset-explained, and locally-closed states, search, persistence, and entry from lock and unlock prompts plus settings. Help navigation, ticket export, bulk management, storage-refusal handling, no-network proof, localization, accessibility, and built-artifact evidence are pending.
